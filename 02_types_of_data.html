Types of Data

You can't analyze data you don't understand. Before touching any formula or model — know what type of data you're dealing with. Everything flows from this.

Mistake to Avoid
§1
Why Does Data Type Matter?

I've seen this mistake a hundred times in my career — a junior DS calculates the mean of a rating column (like "customer satisfaction: 1 to 5"), presents it in a report, and the entire conclusion is wrong. Not because the math was wrong — but because you can't take a mean of ordinal data.

Data type determines which operations are valid, which statistics you can calculate, and which models you can use. Get this wrong, and everything downstream is garbage — even if your code runs perfectly.

Every data point in your dataset has a type. That type is not just a technical label — it's a contract that tells you what you're allowed to do with it mathematically. Violate that contract and your analysis is invalid.

❌ Wrong Approach

Calculate the average of "City" column (Mumbai=1, Delhi=2, Bangalore=3). "Average city = 1.8" — this means absolutely nothing. City is nominal data. Averaging it is mathematically meaningless.

✅ Right Approach

For nominal data like "City", use Mode (most frequent value) or count frequencies. "Mumbai appears 45% of the time" — now that's a valid, meaningful stat.

§2
Qualitative vs Quantitative

This is the first and most fundamental split. Every column in every dataset you will ever work with is either Qualitative (describes quality/category) or Quantitative (describes quantity/number). Master this split first — everything else builds on top of it.

Type A

🏷️ Qualitative Data

Also called Categorical data. It describes qualities or characteristics — things that fall into categories, not numbers. You can't do arithmetic on it (no adding, subtracting, averaging).

Ask yourself: "Does it make sense to add two of these together?" If no → it's qualitative.

Gender City Blood Group Product Category Customer Feedback Yes / No
DS Context
E-commerce: Product category (Electronics, Clothing, Books). You can count how many products are in each category. You can find the most popular category. But "Electronics + Books = ?" makes no sense.
Type B

🔢 Quantitative Data

Also called Numerical data. It's data that represents actual measurable quantities — things you can count, add, subtract, average. The arithmetic is meaningful here.

Ask yourself: "Does adding two of these together make sense?" If yes → it's quantitative.

Age Salary Temperature Number of Orders Revenue Height / Weight
DS Context
Banking: Customer age (32 years), income (₹8.5L/yr), loan amount (₹50L). You can average these, find distribution, calculate correlations. Age 30 + Age 40 / 2 = Average age 35 → perfectly valid.
§3
Discrete vs Continuous

This is the sub-split inside Quantitative data. Once you know something is a number — the next question is: can it take any value in a range, or only specific fixed values? This distinction matters for which probability distributions you use and how you visualize the data.

Quantitative Sub-type A

🎲 Discrete Data

Data that can only take specific, separate, countable values. Usually whole numbers. You can count them — and there are clear "gaps" between possible values. You can't have 2.5 children.

Key test: Can the value be a fraction in real life? If no → Discrete.

No. of children No. of orders placed No. of employees Dice roll (1–6) No. of complaints
Real Project Example
Telecom: Number of customer support calls per month. It's 0, 1, 2, 3... never 1.7 calls. We used a Poisson distribution to model this — a distribution designed specifically for discrete count data.
Quantitative Sub-type B

📈 Continuous Data

Data that can take any value within a range, including fractions and decimals. Measured, not counted. The precision depends only on your measuring instrument.

Key test: Can this value theoretically be measured more precisely? If yes → Continuous.

Age (exact) Temperature Revenue (₹) Weight / Height Time spent on app
Real Project Example
Healthcare: Patient blood pressure (122.4 mmHg), body temperature (98.6°F), response time to drug (4.32 hours). All continuous — we used Normal distribution and regression models, which require continuous targets.
💡 Quick memory trick: Discrete = you can count on your fingers (1, 2, 3...). Continuous = you need a ruler or scale to measure it, and you can always go one decimal place further.
§4
Scales of Measurement — The 4 Levels

This is where most people get confused — and where understanding really separates a mediocre DS from a great one. There are 4 levels of measurement, each more powerful than the previous. Higher level = more mathematical operations allowed. The levels are cumulative — each one adds a new property on top of the previous.

Level 1 · Nominal

Named Categories

Data is just labels or names. No order, no ranking, no math. Just different buckets. Think of it as stickers on boxes — they identify, nothing more.

Properties
✓ Can categorize
✗ Can rank/order
✗ Meaningful difference
✗ True zero point
📌 Gender (M/F), Blood group (A, B, O, AB), Eye color, City name, Payment method (Cash/Card/UPI)
2
Level 2 · Ordinal

Ranked Order

Data has a meaningful order/rank — but the gaps between ranks are not equal. You know 1st is better than 2nd, but not by how much exactly.

Properties
✓ Can categorize
✓ Can rank/order
✗ Meaningful difference
✗ True zero point
📌 Customer satisfaction (1–5 stars), Education level (High school → UG → PG → PhD), Movie rating (Bad/Avg/Good/Excellent), T-shirt size (S/M/L/XL)
3
Level 3 · Interval

Equal Gaps, No True Zero

Has all ordinal properties + the differences between values are meaningful and equal. But zero doesn't mean "absence" — it's just another point on the scale.

Properties
✓ Can categorize
✓ Can rank/order
✓ Meaningful difference
✗ True zero point
📌 Temperature in °C/°F (0°C ≠ "no temperature"), Calendar year (Year 0 doesn't mean "no time"), IQ score, Credit score range
4
Level 4 · Ratio

The Full Package

Has everything — order, equal intervals, and a true meaningful zero. Zero actually means "none/absence". Ratios between values are meaningful: "twice as much" makes sense.

Properties
✓ Can categorize
✓ Can rank/order
✓ Meaningful difference
✓ True zero point
📌 Age (0 = just born), Salary (₹0 = no income), Height, Weight, Revenue, Number of orders, Distance, Time duration
💡

The temperature trap (most common interview question): Temperature in Celsius is Interval, NOT Ratio. Why? Because 0°C doesn't mean "no temperature" — it just means the freezing point of water. So saying "40°C is twice as hot as 20°C" is mathematically wrong. But 0 kg of weight = literally no weight → that's Ratio. True zero = physical absence of the thing.

§5
Structured vs Unstructured Data

This is the modern DS reality check. The types above (nominal, ratio, etc.) all live inside structured data — clean tables, rows, columns. But in the real world, 80% of all data generated is unstructured. As a DS, you need to know the difference and know which tools handle each.

Type 01

🗄️ Structured Data

Organized in a predefined format — rows and columns, like a spreadsheet or SQL table. Each cell has a defined data type. Easy to store, query, and analyze. This is what classical statistics was built for.

📊 SQL Databases
📋 Excel / CSV files
📱 CRM records
💳 Transaction logs
📦 Inventory tables
Tools Used
SQL Pandas Excel Tableau Power BI
Type 02

📁 Unstructured Data

No predefined format. It's raw, messy, and requires heavy processing before analysis. Think emails, images, audio, social media posts, PDFs. Can't just dump this in a table and run a SQL query.

💬 Customer reviews (text)
🖼️ Product images
🎵 Audio recordings
📧 Emails / Chats
📹 CCTV footage
Tools Used
NLP / spaCy BERT / GPT OpenCV PyTorch Whisper
🚀 Semi-structured data also exists — JSON, XML, logs, HTML. It has some structure (key-value pairs) but isn't a clean table. REST API responses are semi-structured. You'll deal with this a lot in real projects. Tools: Python (json module), MongoDB, Spark.

Real Project — All Data Types in One
⚡ Real Project · Customer Churn Prediction · Telecom

Airtel-Style Telecom Churn Model — Predicting Who Will Leave Next Month

A telecom client with 4 million subscribers. Task: predict which customers will cancel their subscription in the next 30 days. This single project used every type of data we just covered.

Qualitative Data Used
Plan type (Prepaid/Postpaid) → Nominal
Customer satisfaction survey (1–5) → Ordinal
Region (North/South/East/West) → Nominal
Complaint category (Network/Billing/Service) → Nominal
Quantitative Data Used
Customer age → Ratio (continuous)
Monthly bill amount → Ratio (continuous)
Number of support calls → Ratio (discrete)
Account activation year → Interval
Unstructured Data Used
Customer complaint text → NLP sentiment extracted
Call center transcripts → Topic modeling applied
Complaint emails → Converted to structured features
App reviews → Sentiment score (−1 to +1)
💡 Key insight: The satisfaction rating (ordinal) was the strongest predictor — but only after we treated it correctly as ordinal, not as a ratio. Treating it as ratio (and averaging it) gave a weaker model. Knowing data types = better model. We achieved 87% recall on churners — reduced monthly churn by 19%.

Chapter Summary

What you must take away from this chapter ↓

Data type = what operations are valid. Get the type wrong → your statistics and models are wrong, even if the code runs perfectly.

Qualitative = categories (no math). Quantitative = numbers (math is valid). First split to make before anything else.

Discrete = countable, whole values. Continuous = any value in range. This decides which probability distribution to use.

4 scales: Nominal → Ordinal → Interval → Ratio. Each level adds one more mathematical superpower. Ratio is the most powerful.

True zero test = the key to Ratio. Zero must mean "complete absence" of the thing. Temperature in °C fails this. Age, revenue, weight pass it.

80% of real-world data is unstructured. Text, images, audio — these need NLP and deep learning before they become analyzable structured data.
